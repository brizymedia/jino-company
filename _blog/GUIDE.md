# 지노컴퍼니 블로그 작업 설명서

지노컴퍼니(JINO CP., 행사전문 인력에이전시) 홈페이지의 **행사 인력 블로그**(`/blog/`)에 글을 올릴 때 따르는 규칙이다. 사람이 고칠 때도 이 문서를 먼저 고친다.

- 읽는 사람: 기업 · 기관의 행사 담당자와 마케터.
- 목표: 네이버 · 구글 · AI 검색(챗GPT · 퍼플렉시티 등)에서 「행사 진행요원 · 안내 요원 · 주주총회 운영 · 팝업스토어 인력 · 박람회 부스 인력 · 의전 · 통역」 검색에 걸리는 것. 광고가 아니라 **담당자가 저장해 두고 싶은 체크리스트**여야 한다. 정의 · 단계 · 체크리스트 · 표 중심으로 쓰면 AI 검색에 인용되기 좋다.
- 원칙: 틀린 정보 한 줄이 글 한 편보다 해롭다. **확인 못 한 것은 쓰지 않는다.**
- 이 블로그는 지역 글이 아니라 **행사 인력 운영 실무 글**이다. 그래서 모든 글의 `region` 은 `common` 이고, 지역별 모음 · 지역 근거 칸은 없다.

## 1. 순서

1. `node scripts/blog-plan.mjs` 로 다음에 쓸 주제를 받는다(`_blog/keywords.json`).
2. 글마다: 아래 「쓸 수 있는 회사 사실」 범위 안에서만 회사 이야기를 하고, 법 · 기준을 말하려면 `_blog/sources.json` 의 출처와 그 `사실` 범위 안에서만 쓴다(지금은 비어 있어 법 · 기준 이야기를 쓰지 않는다). 사진은 `_blog/photos.json` 에서 3~4장.
3. `_blog/posts/<날짜>-<slug>.json` 을 쓴다(3장).
4. `node scripts/blog-check.mjs` (새 글만이면 `--new <파일>`)가 통과할 때까지 고친다. 통과시키려고 지어낸 문장을 끼워 넣지 않는다.
5. 빌드: **`python tools/build_site.py` → `python tools/blog_shell.py` → `node scripts/build-blog.mjs`** (이 순서, python 은 `-I` 없이, `PYTHONUTF8=1`). build_site.py 가 sitemap.xml · llms.txt 를 덮어쓰므로 블로그 빌드는 항상 그 뒤에. `blog_shell.py` 는 build_site.py 의 머리 · 꼬리를 `_blog/shell.json` 으로 옮긴다(메뉴 · 연락처가 바뀌면 다시).
6. 결과 HTML(`blog/`)은 손으로 고치지 않는다.

## 2. 절대 쓰지 않는 것 (검사기가 일부를 막는다)

- **가격 · 단가 · 「○○원」 · 「만 원」** — 견적은 문의로 받는다.
- **후기 · 만족도 · 평가 · 고객 이름 · 기업 실명 · 기관 실명 · 실제 행사 이름**(사이트 「주요 행사」 22곳의 이름도 블로그에서는 쓰지 않는다). 사진 캡션도 같다 — 행사 종류만 쓴다.
- **참석 인원 · 인력 투입 수 · 비율 · 건수** 같은 구체 숫자 주장. 「몇 명 필요」 기준표 대신 판단 항목 · 질문 목록으로 쓴다.
- 안전 인증 · 보험 · 수상 · 자격 보유, 법 조항 · 법령 이름(확인한 출처가 없다).
- 회사 경험 늘려 말하기(「~해 왔습니다」「풍부한 경험」「노하우」). 아래 사실 범위 안에서만 말한다.
- 다른 회사 · 다른 고객 사이트 이름, 「무조건 · 100%」, 지어낸 통계.
- 우리가 서비스로 내걸지 않은 것(장비 대여 · 음향 · 조명 · 무대 설치 · 케이터링 · 경호 · 의료인 상주 · 문서 번역 등)을 해 준다는 약속.
- 얼굴이 크게 나온 사진, 고객사 이름이 크게 보이는 사진, `photos.json` 에 없는 사진.
- 비상 상황 글은 **일반 상식 수준**으로만(119 신고 · 알리기 · 대피 안내 · AED 사용은 기기 음성 안내를 따른다). 구체 수치 · 의학적 절차 · 법 조항은 쓰지 않는다.

## 3. 글 형식 (JSON)

| 칸 | 규칙 |
|---|---|
| `slug` | 한글 · 영소문자 · 숫자와 `-`, 70자 이하 |
| `date` | `YYYY-MM-DD` (오늘보다 뒤 안 됨). 파일 이름 `<date>-<slug>.json` |
| `region` | 항상 `common` |
| `topic` | `keywords.json` 의 topic. 같은 topic 은 한 번만 |
| `category` | 카드 · 머리말에 나오는 분류(`인력 구성` · `현장 운영` · `안전` · `계약`) |
| `title` | 15~50자, 핵심 키워드를 통째로 |
| `description` | 70~160자 |
| `keyword` | `{ "main", "sub": [] }` |
| `lead` | 80~420자, 첫 문장에 핵심 키워드와 결론 |
| `points` | 3~5개 |
| `cover` | `{ path, alt, caption }` |
| `sections` | 4~8개 `{ h2, blocks }` — blocks: `p` `ul` `ol` `table` `img` `tip` |
| `faq` | 2~6개 |
| `sources` | 법 · 기준 · 기관을 말했으면 필수. 주소는 `sources.json` 그대로. 없으면 `[]` |

꾸밈은 `**굵게**` 와 `[글자](/주소)` 뿐. 사이트 안 링크는 `/contact.html#form` 처럼 `/` 로 시작해 쓰면 빌더가 쪽 깊이에 맞는 상대 경로로 바꾼다(이 사이트는 `…github.io/jino-company/` 하위 경로에 있다가 도메인으로 옮겨 가므로 절대 경로를 쓰지 않는다).
